# NALLM Artifact

Companion artifact for **"NALLM: Evidence-Stratified Prompting of an LLM
for Real-time Name Disambiguation, Enhanced by a Statistical Model"**
(PVLDB Vol. 20 submission).

NALLM assigns each incoming paper to one of its name-sharing author
profiles, or to none (NIL). A general-purpose LLM, without task-specific
training, makes every attribution decision; an untuned 19-feature LightGBM
arbitrates only *whether* to trust each decision. The system ranks first on
the official WhoIsWho RND leaderboard (weighted F1 0.93951).

## Data — not included, by design

WhoIsWho v3 data is distributed under the benchmark's own license
(https://github.com/THUDM/WhoIsWho) and must be obtained through the
official channel; it also contains the valid-split ground truth, so we do
not redistribute it. The two frozen test-side pipeline snapshots that
`run_repro.sh` consumes (stage-4 LLM decisions; per-candidate 19-d
features — no ground truth involved) are attached to this repository's
GitHub Release as gzip archives; download them into `data/` and verify
against:


## Three reproduction paths

1. **Arbitration-stage postprocessing (decision level).** With the two snapshots in
   `data/`:
   ```bash
   bash run_repro.sh   # ends with verify.py; exit code 0 = reproduction hit
   ```
   The comparison baseline is shipped: `verify.py` falls back to
   `archives/test_deepseek_postprocessed.json` (byte-identical to the
   original scored output). Verified end-to-end: 53 diffs → 99.6340%
   agreement, exit 0.
2. **Full pipeline re-run (LLM stage included).** The recall, subtyping,
   prompt, and arbitration stages run end-to-end from code
   (`scripts/run_llm_first.py`; batch variant `run_llm_first_batch.py`).
   The LLM stage requires your own API credentials via environment
   variables — see `src/nallm/disambiguation/llm.py`.
3. **Claim verification from shipped outputs.** All submission files and
   result tables are included; no data download needed. Every leaderboard
   number in the paper corresponds to one of the archived submissions.

## Notes

- **Similarity provenance.** The title / organization / venue similarities
  that drive candidate recall (t=0.55 on best-paper title similarity),
  subtyping, prompts, and arbiter features were computed with
  **Qwen3-Embedding-4B** (2560-d, locally deployed; `EMBEDDING_MODEL` in
  `src/nallm/core/config.py`, overridable via environment). The shipped
  pipeline consumes precomputed similarity matrices; re-computing them
  requires an embedding endpoint.
- **Taxonomy in code.** The 16 subtype strings (built in
  `classification/subtype_llm_first.py`) dispatch to 10 strategies (enum
  `DisambiguationStrategy`): `AUTO` (strong-evidence bypass), `NONE`
  (no candidates), and 8 evidence-calibrated prompt types
  (`SYSTEM_PROMPT_MAP`: p0_low/medium/high, p1_high/medium/weak/comp,
  p2_p3). `standard` and `simplified` are auxiliary prompt modes, not
  dispatch targets -- the naive-prompt ablation forces `standard`.
- **Stage numbering.** The paper numbers the pipeline 1--5 (recall,
  subtyping, dispatch, LLM judgement, arbitration). Some in-code comments
  use the historical internal numbering where the LLM stage is written as
  ``③`` and the arbitration stage as ``⑥``; the mapping is 3 = stage 4,
  6 = stage 5.
- `*_llm_only` is not a bare LLM: it is the pipeline minus the arbitration stage (recall,
  subtyping, dispatch, and the strong-evidence bypass all included).
- Thresholds theta_a=0.14, theta_b=0.20 are frozen
  pipeline constants (selected on valid; the selection-leakage split-half
  experiment is `scripts/theta_transfer_valid.py`).
- The postprocessing module checks candidate-consistency before scoring to
  prevent a silent feature/candidate-pool mismatch (`postprocess/`).
